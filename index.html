Quick Start

1. Download the library

Vex is a single file. Download it and drop it into your bot.

Or view the source on GitHub.

2. Place it next to your main file

Put the downloaded vex.py in your bot's main directory, right beside the file that starts your bot (often main.py or bot.py). No installation or pip command is needed.

your-bot/
  ├── main.py
  ├── vex.py  # <- drop the downloaded file here
  ├── requirements.txt
  └── cogs/
      ├── tickets.py
      └── giveaways.py

Because vex.py sits beside main.py, you can import it directly from anywhere in your project.

3. Import and build

import vex

view = (
    vex.vex()
    .h2("Hello World")
    .text("This is a Components V2 message.")
    .button(
        vex.button()
        .label("Click me")
        .primary()
        .on_click(lambda i: i.response.send_message("Clicked!", ephemeral=True))
    )
)

await view.send_to(channel)

What is Vex V2.4

A fluent, minimal builder library for Discord Components V2 (Layout Views) in Python. Vex wraps discord.py V2 primitives with chainable APIs, pre-built paginators, confirmation flows, modals, cooldown utilities, a lightweight command help registry, live views, wizards, polls, argument converters, and a full theming system.

Vex

Inherits discord.ui.LayoutView. The primary canvas for V2 messages.

Commands & Checks

Vex provides decorators for defining slash, hybrid, and grouped commands, plus a set of checks that work on both application commands and prefix commands. Inside a vex.Cog the commands register automatically; defined at module level they are queued and picked up by the bot on load.

Command Decorators

DecoratorDescription
@vex.slash_cmd(...)Define an application (slash) command. Name defaults to the function name; description falls back to the docstring.
@vex.hybrid_cmd(...)Define a command usable as both a slash command and a prefix command.
@vex.slash_group(name, ...)Create a slash command group. Aliases: group, command_group.
@vex.hybrid_group(name, ...)Create a hybrid command group.
@vex.cmd(name, aliases=[...])Define a classic prefix command.

slash_cmd / hybrid_cmd parameters

ParameterDescription
nameCommand name. Defaults to the function name, lowercased with spaces turned into dashes.
descriptionShown in the command picker. Falls back to the function docstring.
guild / guildsRestrict registration to one or more guilds for instant updates during development.
nsfwMark the command as age-restricted.
categoryGrouping label used by the help registry.
aliases (hybrid)Alternate prefix invocations.

Checks

Checks decorate a command and run before it executes. They apply to slash and prefix commands alike.

CheckDescription
@vex.owner_onlyOnly the bot owner may run the command.
@vex.guild_onlyDisallow use in DMs.
@vex.dm_onlyOnly usable in direct messages.
@vex.nsfw_onlyOnly usable in age-restricted channels.
@vex.has_permissions(**perms)Require the invoking user to hold the given permissions, e.g. administrator=True.
@vex.bot_has_permissions(**perms)Require the bot to hold the given permissions.
@vex.has_role(role)Require a specific role by id or name.
@vex.has_any_role(*roles)Require at least one of the listed roles.
@vex.cooldown(rate, per, bucket="user")Rate-limit the command. Bucket can be "user", "guild", "channel", or a BucketType.
@vex.guild_cooldown(rate, per)Cooldown shared across an entire guild.
@vex.check(predicate)Custom check from any predicate callable.

Example

class Tickets(vex.Cog):
    panel = vex.slash_group("panel", description="Manage ticket panels.", guild_only=True)

    @vex.slash_cmd(description="Close the current ticket.")
    @vex.guild_only
    @vex.cooldown(1, 10)
    async def close(self, interaction: discord.Interaction, reason: str = None):
        await interaction.response.send_message("Closing...")

    @panel.slash_cmd(description="Create a new panel.")
    @vex.has_permissions(administrator=True)
    async def create(self, interaction: discord.Interaction, name: str):
        await interaction.response.send_message(f"Created {name}")

async def setup(bot):
    await bot.add_cog(Tickets(bot))

Groups

A SlashGroup created with vex.slash_group() exposes its own .slash_cmd() decorator for subcommands, producing commands like /panel create. Discord supports a single level of nesting, so a group's subcommands cannot themselves be groups.

Converters

vex.convert provides argument converters that resolve a mention, raw ID, or name into a Discord object. Each converter works as a type annotation in both slash commands and prefix commands at once, and falls back to a REST fetch when the target is not cached. Built around accepting user mention, ID, and username by default.

Converters

AnnotationResolvesAccepts
vex.convert.user()UserMention, ID, username, display name, prefix match. REST fetch fallback.
vex.convert.member()MemberSame as user, narrowed to the current guild with a fetch_member fallback.
vex.convert.role()RoleRole mention, ID, exact name, prefix match.
vex.convert.channel()ChannelChannel mention, ID, name (with or without leading #).
vex.convert.duration(minimum=, maximum=)int (seconds)Strings like 1d12h, 90m, 2h30m. Optional bounds in seconds.
vex.convert.emoji()str / EmojiUnicode and custom emoji.

Options

ParameterDescription
optional=TrueMakes the parameter non-required and returns None on a miss instead of raising.
minimum / maximumDuration only. Reject values outside the range, in seconds.

Behaviour

  • In slash commands, user(), member(), role(), and channel() register as native Discord option types, so the client shows the proper picker.
  • A failed conversion raises vex.ConvertError, which subclasses both commands.BadArgument and app_commands.AppCommandError, so a single error handler can catch it.
  • With optional=True a miss yields None rather than an error.

Example

class Mod(vex.Cog):
    @vex.slash_cmd(description="Look up a member.")
    async def whois(self, interaction: discord.Interaction, target: vex.convert.user()):
        await interaction.response.send_message(f"{target} ({target.id})")

    @vex.slash_cmd(description="Start a timed giveaway.")
    async def gw(self, interaction: discord.Interaction,
                 length: vex.convert.duration(minimum=30),
                 host: vex.convert.member(optional=True) = None):
        host = host or interaction.user
        await interaction.response.send_message(f"{length}s giveaway by {host}")

Presence

Identity spoofing for the Discord gateway IDENTIFY payload. Patches the websocket so the bot reports a specific client platform on every fresh session. Changes take effect immediately by forcing a re-IDENTIFY via the gateway INVALIDATE_SESSION mechanism.

PresenceHandler

Class-level (all methods are classmethods). No instantiation needed.

MethodDescription
apply(profile, *, bot=None)Apply a named profile or custom dict. Patches the websocket if not already patched. If bot is provided, schedules a re-IDENTIFY via bot.loop.create_task.
apply_async(profile, *, bot)Async version. Applies the profile then awaits reidentify_all. Use inside setup_hook or command handlers.
restore(*, bot=None)Remove all patches and clear the active profile. Optionally triggers re-IDENTIFY.
restore_async(*, bot)Async version of restore. Awaits reidentify_all after patching out.
reidentify_all(bot)Async. Sends an INVALIDATE_SESSION payload to each shard's websocket, forcing a fresh IDENTIFY on reconnect.
current()Returns the active profile dict or None.
profiles()Returns list of built-in profile name strings.
desktop(*, bot=None)Shorthand for apply("desktop", bot=bot).
mac(*, bot=None)Shorthand for apply("mac", ...).
linux(*, bot=None)Shorthand for apply("linux", ...).
mobile(*, bot=None)Shorthand for apply("mobile", ...). Bot appears on iOS.
android(*, bot=None)Shorthand for apply("android", ...).
vr(*, bot=None)Shorthand for apply("vr", ...).
web(*, bot=None)Shorthand for apply("web", ...). Bot appears as browser client.
embedded(*, bot=None)Shorthand for apply("embedded", ...).

Top-level function

FunctionDescription
presence(profile, *, bot=None)Calls PresenceHandler.apply(profile, bot=bot). Sync shorthand for module-level use.

How it works

On first apply call, two discord.py gateway methods are monkey-patched: DiscordWebSocket.identify (stamps the active profile onto the ws instance) and DiscordWebSocket.send_as_json (injects os, browser, device into IDENTIFY op payloads). The active profile is read live at identify time, so switching profiles mid-session with apply_async takes effect on the very next IDENTIFY.

reidentify_all delivers a synthetic INVALIDATE_SESSION (op 9, d: false) directly to each shard's websocket. Discord.py's gateway handler processes this exactly as if Discord had sent it: it clears session state and raises ReconnectWebSocket(resume=False), which routes through the shard worker as EventType.identify, resulting in a fresh IDENTIFY with the new properties.

Example

import vex

# In setup_hook (awaited, takes effect before bot is fully ready)
async def setup_hook(self):
    await vex.PresenceHandler.apply_async("mobile", bot=self)

# In a command (switch at runtime)
@bot.command()
async def setpresence(ctx, profile: str):
    await vex.PresenceHandler.apply_async(profile, bot=bot)

# Custom profile
vex.PresenceHandler.custom(bot=bot, os="Linux", browser="Firefox", device="")

# Restore default identity
await vex.PresenceHandler.restore_async(bot=bot)

# Check active profile
print(vex.PresenceHandler.current())
# {'os': 'iOS', 'browser': 'Discord iOS', 'device': 'discord_ios'}

# List available profiles
print(vex.PresenceHandler.profiles())
# ['desktop', 'mac', 'linux', 'mobile', 'android', 'vr', 'web', 'embedded']
